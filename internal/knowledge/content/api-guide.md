# API и Swagger

Swagger открывается из раздела **API и MCP** по ссылке `/swagger`. Нужны `api_docs.read` и включённый Swagger в YAML и административных настройках. `/api/v1/openapi.json` содержит OpenAPI 3.0.3, модели запросов/ответов, параметры, права и ошибки. Swagger запрашивает подтверждение перед записью.

## Аутентификация и права

Для автоматизации создайте токен с audience `api`, конкретными scopes и группами нод, задайте срок. Секрет показывается один раз. Передавайте `Authorization: Bearer …` в заголовке; не помещайте секрет в URL. MCP требует отдельную audience `mcp` и использует `/mcp` Streamable HTTP, а не REST-модели Swagger.

Эффективные права — пересечение актуального RBAC владельца, scopes и областей токена. Токен не повышает права и перестаёт работать при отзыве/истечении. Для операции над своей учёткой через токен может понадобиться scope `self`. Управление факторами регистрации, выпуск API-токенов, восстановление сертификата ноды и персональный список доступных хостов используют браузерную сессию, не bearer. Ansible inventory, наоборот, требует bearer.

Браузерная cookie `linpam_session` сохранена для совместимости. При изменениях нужен `X-Heimdall-CSRF: 1`, Origin должен совпадать с адресом Heimdall. Bearer-запросам CSRF не нужен.

```sh
# HEIMDALL_API_TOKEN задайте безопасным способом вне истории shell.
curl --fail-with-body --cacert /path/to/ca.pem \
  -H "Authorization: Bearer ${HEIMDALL_API_TOKEN}" \
  'https://heimdall.example/api/v1/nodes?limit=25&status=healthy&query=web'
```

## Списки и пагинация

Списки возвращают JSON-массив и заголовок `X-Heimdall-Next-Cursor`. Передайте полученный курсор в `after` следующего GET с прежними фильтрами и limit. Пустой курсор означает последнюю страницу. Не разбирайте курсор, не заменяйте его номером страницы. Изменение фильтра начинает просмотр заново.

Граф `/api/v1/access/graph` возвращает объект с `connections` и `recommendations` и тот же cursor header. По умолчанию 25 назначений, максимум 100. Списки статьи и доступных пользователю хостов ограничены 100; остальные публичные коллекции — до 500. Доступные фильтры перечислены у каждой операции Swagger.

Ansible `/api/v1/ansible/inventory` возвращает целый протокольный inventory для `--list`; у него нет пагинации. Он учитывает актуальные native назначения, права `inventory.read` и token scopes/группы.

## Изменение и подтверждение

Большинство изменений возвращают `{"operation_id":"…"}`. Это подтверждение принятия транзакции и постановки доставки, а не выполнения на всех нодах. Читайте `/operations/{id}/targets` с `sync.read`, пока все целевые ноды не станут `applied`. При полном отзыве ACK включает завершение пользовательских процессов. Offline/ошибка означают, что отзыв ещё не подтверждён.

Документация, сообщения и настройки используют optimistic `version`. При создании version=0; при сохранении существующего объекта передайте версию последнего GET. Для удаления сообщения version передаётся query-параметром. При 409 прочитайте актуальный объект; не перезаписывайте чужие изменения автоматически.

## Ошибки

| Код | Действие клиента |
| --- | --- |
| 400 | Исправить JSON/параметры/ограничения модели |
| 401 | Заново войти или проверить токен/audience/срок |
| 403 | Проверить RBAC, scopes, группы, CSRF и факторный минимум |
| 404 | Проверить ресурс/включённость endpoint |
| 409 | Прочитать актуальную версию либо устранить дубликат |
| 429 | Повторить с ограниченным backoff и jitter |
| 500/503 | Показать пользователю ошибку и сохранить контекст запроса |

Стандартная ошибка — `{"error":"Понятное сообщение"}`. Некоторые auth/health ответы содержат пустое тело; клиент должен также учитывать HTTP-код. Не логируйте password, invitation/join/API/recovery secrets, TOTP secret, recovery codes и приватные ключи.

## Агентский протокол

REST `/agent/join` и `/agent/recover` принимает CSR как base64 от PEM и выдаёт сертификат. Далее агент использует mTLS gRPC и проверяет подпись состояния, epoch, node_id и ревизию. Приватные ключи остаются у агента. Прикладной bearer не заменяет сертификат агента. Адреса, доверие к CA и поведение одного `heimdall-agent` описаны в статье о нодах.
