# SSH-ключи и UNIX-пароль

В профиле можно хранить несколько именованных SSH-ключей. Публичные ключи доставляются только на ноды, где роль явно разрешает вход по ключам. Хранение ключа в профиле само по себе доступа не предоставляет.

## Аппаратный ключ

Если политика требует SK, создайте ключ локально:

```sh
ssh-keygen -t ed25519-sk -O verify-required
```

Загрузите содержимое файла `.pub`. Для использования понадобится аппаратный аутентификатор с поддержкой SSH. Обычный WebAuthn Passkey не превращается в SSH-ключ.

## Срок действия

Администратор задаёт TTL и срок предупреждения в **Настройки**. В обзоре и уведомлениях появляется предупреждение о скором истечении. Выпустите новый ключ, проверьте его доступ и отзовите старый. Истёкший или отозванный fingerprint нельзя использовать повторно. Срок ключа проверяется локальным OpenSSH даже при недоступном control plane.

## UNIX-пароль

Это отдельный пароль для ОС. Он не равен паролю Heimdall. Установить его можно только если включена синхронизация пользователя и назначенная UNIX-роль явно разрешает парольный вход. На нодах без этого разрешения хеш не доставляется, локальный пароль блокируется, OpenSSH выключает PasswordAuthentication и keyboard-interactive. Если разрешены только ключи, наличие пароля в другой роли/группе нод не включает его на этой ноде.

Пустое значение в форме удаляет UNIX-пароль. Даже при разрешённом методе пустой пароль не позволяет входить.

## Изменения и отключение

Удаление ключа, блокировка пользователя, снятие роли или выключение синхронизации создают доставляемый отзыв. Сохранённая на ноде учётка блокируется, ключи, пароль и sudo удаляются. При выключении синхронизации UNIX-пароль также удаляется из БД. Локальная учётка и домашний каталог сохраняются для безопасного сопровождения.

На недоступной ноде отзыв не может примениться мгновенно: статус остаётся ожидающим, включаются метрики и уведомления. Успех отображается только после подтверждения агента. При аварии уже применённый доступ сохраняется и не требует работающего агента.
